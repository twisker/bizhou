# 敝帚（Bìzhǒu）— 客户端加密引擎 + CLI · PRD

> **一句话**：一个开源、跨平台的**客户端加密引擎**与命令行工具（`bz`）。在把文件托付给云存储（百度网盘官方 API）之前，先在本地加密，让云端只存密文、无法解析你的内容；取回时自动解密还原。**隐私优先、数据主权。**

| 项 | 值 |
|---|---|
| 项目名 | 敝帚（Bìzhǒu） |
| 仓库 | `bizhou` |
| CLI 命令 | `bz` |
| 平台 | Windows / macOS / Linux |
| 技术栈 | TypeScript + Node（内置 `crypto`） |
| 存储后端 | 用户自己的百度网盘（官方开放平台 API） |
| 授权 | Apache-2.0（开源） |
| 安全模式 | 用户主密码派生密钥（端到端加密） |
| 文档日期 | 2026-07-23 |

---

## 1. 背景与问题

云存储会对上传的文件做内容检测/扫描。你的私人文件在托付给云端之前，**理应能由你自己先加密**，让云端只拿到**密文**、无法解析其中内容——这是数据主权与隐私的基本诉求。

敝帚解决的正是这件事：**客户端加密 → 上传密文 → 取回自动还原**。云端只见到一坨无法识别的密文，读不到你的真实内容。

---

## 2. 目标与非目标

### 2.1 目标

1. 文件上传前**客户端加密**（端到端），云端及中途第三方**无法解析内容**。
2. 取回时**自动解密还原**，字节级一致。
3. 支持**大文件**（突破云端单文件大小上限）。
4. 为加密文件提供**自建预览**（视频/音频/图片）。
5. 文件可**分享**（密钥交接 / 导出标准归档）。
6. **多账号**切换。
7. **Win/macOS/Linux 三平台**一致。
8. 以 **CLI（`bz`）** 提供全部能力；核心库可被任意前端/自动化**嵌入**，可发布为 agent 工具（Skill）。

### 2.2 非目标

- 不重写云盘客户端、不替代云端做存储。
- 不走逆向/破解接口——仅用官方开放平台 API。
- 不做移动端（首期桌面 + CLI）。

---

## 3. 威胁模型与安全定性

- **要防的**：云端（及中途第三方）对文件内容的**自动化批量扫描**。AES 加密使其读到的只是密文。
- **安全强度**：**用户主密码派生 KEK**（见 §7）——DEK 被主密码派生的 KEK 包裹，**没有主密码，任何人都解不开**。真端到端加密。代价：忘主密码=资源锁死（恢复密钥兜底）。
- 密钥**全程只在客户端**，不上传、不托管。

---

## 4. 核心概念与术语

| 术语 | 定义 |
|---|---|
| **资源（Resource）** | 用户视角的"一个文件"。物理上是一个 **Bundle 文件夹**。 |
| **Bundle** | 带特定后缀（`.bz`）的文件夹，装下一个资源的全部物料：加密分片 + 预览包 + manifest。在别的客户端里显示为普通文件夹（类比 macOS `.app` bundle）。 |
| **分片（Chunk）** | 资源内容经（可选压缩 +）AES-256-GCM 加密后切成的块（默认每片 100MB）。 |
| **预览包（Preview Pack）** | 资源的轻量预览，单独加密、体积极小，浏览时率先下载。 |
| **Manifest** | 资源清单：分片信息、被包裹的密钥、加密的元数据、预览指向。 |
| **资源密钥（DEK）** | 每资源随机生成的 AES-256 密钥，加密该资源内容。 |
| **KEK** | Key-Encryption-Key，加密（包裹）DEK。由用户主密码派生。 |
| **信封加密** | DEK 加密内容，KEK 加密 DEK，DEK 密文存 manifest。 |

## 5. 系统架构 —— 核心库 + CLI

```
┌──────────────────────────┐
│   核心库 @bizhou/core     │  纯逻辑，无交互，发进度事件
│  crypto / bundle / chunker│
│  baidu-api / preview / 7z │
└────────────┬─────────────┘
             │
      ┌──────▼──────┐
      │  CLI (`bz`)  │  薄包装；可测、可脚本化、可发布为 Skill
      └─────────────┘
```

- **Layer 1 · 核心库（`@bizhou/core`）**：加密（AES-256-GCM 信封）、bundle/manifest、分片器、百度 OpenAPI 客户端、预览生成、7z-AES 导出。**只发进度事件、不 print**；所有交互留在外层；无 UI/CLI 依赖，可被任意前端或自动化（daemon、定时备份等）嵌入。
- **Layer 2 · CLI（`bz`）**：核心库的命令行包装，可测、可脚本化、可发布为 PAI Skill 供 agent 调用。

## 6. 数据模型与存储结构

### 6.1 Bundle 目录结构（存于 `/apps/bizhou/` 下）

```
/apps/bizhou/
  └── <opaque-id>.bz/          # 文件夹名为不透明 ID（不泄露原文件名）
        ├── manifest.json
        ├── 000.part           # 加密分片 0（≤100MB）
        ├── 001.part
        ├── ...
        └── preview.part       # 加密预览包（可选）
```

- 文件夹名**不透明**（随机/时间序 ID），不含原文件名。
- 原文件名只在（加密的）manifest 里；别的客户端只见不透明文件夹。

### 6.2 manifest.json Schema（首版）

```jsonc
{
  "version": 1,
  "bundleId": "<opaque-id>",
  "createdAt": "<ISO8601>",
  "cipher": "AES-256-GCM",
  "compression": "none | gzip | zstd",
  "kdf": { "algo": "scrypt|argon2id", "salt": "<b64>", "params": { } },
  "wrappedKey": "<base64>",              // DEK 被 KEK(主密码派生) 包裹后的密文
  "chunkSize": 104857600,
  "chunks": [
    { "seq": 0, "file": "000.part", "plainSize": 104857600, "iv": "<b64>", "tag": "<b64>", "sha256": "<hex>" }
  ],
  "preview": { "file": "preview.part", "kind": "video|audio|image", "iv": "<b64>", "tag": "<b64>" },
  "encMeta": "<base64>"                  // 用 DEK 加密的敏感元数据（原文件名/大小/类型）
}
```

- **明文**：操作性字段（分片数/大小/iv/tag/hash、KDF 参数、wrappedKey）。iv 与 GCM tag 按标准可明文。
- **加密**：`encMeta`（原文件名等），用 DEK 加密。

## 7. 加密与密钥架构

### 7.1 算法

- **AES-256-GCM**（AEAD：机密性 + 完整性/防篡改）。用各语言内置标准库（Node/Bun `crypto` 等），**零外部二进制依赖**。
- 加密对象是原始字节流 → 无"归档中央目录明文文件名"泄露。

### 7.2 压缩（可选）

- 启用则**先压缩再加密**（gzip/zstd）；媒体文件默认关闭。

### 7.3 信封加密 + 主密码派生 KEK

- 每资源随机 **DEK** 加密内容；**KEK 包裹 DEK** → `wrappedKey` 存 manifest。
- **KEK 由用户主密码经 KDF（scrypt / argon2id，加盐）派生**。代码中无任何秘密，可审计。
- **真安全**：没有主密码，任何人都解不开。**机器无关**：换机/重装只需重输主密码。
- **恢复密钥**：初始化生成恢复码/恢复密钥文件，用户离线保管；忘主密码时用它恢复。
- **降低摩擦**：主密码**每设备解锁一次**，派生的 KEK 缓存进 OS 安全存储（钥匙串/Credential Manager）供本设备会话使用。

## 8. 分片与上传

### 8.1 两层分片

- **逻辑层（本工具，100MB）**：把资源切成 ≤100MB 加密分片存为多个云端文件，**绕开云端单文件大小上限**。
- **传输层（云端原生，4MB）**：上传接口按 4MB 分片，自带 `uploadid` 断点续传——直接复用。

### 8.2 上传流程（每个分片文件）

```
precreate  → 拿 uploadid
superfile2 → 逐 4MB 片上传（partseq）
create     → 合并落盘到 /apps/bizhou/<bundle>/NNN.part
```

- 切片触发默认：文件 >100MB 才切；每片 100MB（可配置）。

---

## 9. 预览机制

- 针对视频/音频/图片：上传时客户端生成预览物料（视频抽帧/音频截段/图片缩略），单独加密为 `preview.part`，体积极小。
- 浏览到该资源时率先下载预览包并本地解密展示，无需下载完整资源。
- 动机：加密使云端原生预览失效 → 自建轻预览层补回体验。

---

## 10. 分享

> 采用主密码派生 KEK，资源 wrappedKey 只有你能解 → 分享须**显式交接密钥**。

- **交接密钥模式**：对某资源生成**分享码**（该资源 DEK 的导出串）。把云端文件夹链接 + 分享码给对方，对方用敝帚 + 分享码解密（绕过你的 KEK）。分享码按需生成、可失效。
- **导出标准归档**：把资源本地合并还原后重打包为 **7z-AES + 头部加密**（藏文件名）→ 对方用 7-Zip / Keka / p7zip + 密码即可解，无需本工具。

## 11. 百度开放平台集成

- **凭证**：用户**自行配置**百度开放平台应用凭证（AppKey / SecretKey）。工具自身**不内嵌任何凭证**。
- **鉴权**：OAuth2.0。CLI 走"开浏览器 + 本地回调端口"或 device-code 流。
- **沙盒**：应用只能操作 `/apps/{产品名}/` 一个目录 → 本工具固定 `/apps/bizhou/`。
- **单文件上限**：普通用户 4GB / SVIP 20GB（§8.1 用 100MB 分片规避）。
- **接口族**：`xpan/file`（precreate/create/list/…）、`pcs/superfile2`（分片上传）、download。

## 13. 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 语言 | TypeScript | 单语言、生态成熟 |
| 运行时 | Node / Bun | 内置 `crypto` 直供 AES-256-GCM + scrypt，零外部依赖 |
| 大文件加密 | `worker_threads` | 避免阻塞 |
| 百度对接 | 直连 REST + OAuth2 | 官方无 JS SDK，REST 易调 |
| 7z 导出 | 7z 库（如 `node-7z` + `7zip-bin`） | 头部加密藏文件名 |

## 14. CLI 规格（`bz`）

| 命令 | 说明 |
|---|---|
| `bz init` | 首次设置主密码，生成恢复密钥 |
| `bz unlock` | 输入主密码解锁本设备会话（缓存至 OS 钥匙串） |
| `bz login` | OAuth 登录百度（浏览器 + 本地回调） |
| `bz logout` | 注销当前账号 |
| `bz account [list\|use <name>\|add]` | 多账号管理与切换 |
| `bz push <path> [--no-split] [--chunk 100MB] [--compress]` | 加密 + bundle + 上传 |
| `bz pull <name\|id> [--out <dir>]` | 下载 + 解密 + 合并还原 |
| `bz ls [path]` | 列出资源（读 manifest 显示真名） |
| `bz info <name\|id>` | 查看资源元数据 |
| `bz preview <name\|id>` | 拉取并展示预览包 |
| `bz share <name\|id> [--code\|--7z] [--out <file>]` | `--code` 生成分享码；`--7z` 导出 7z-AES 单包 |
| `bz rm <name\|id>` | 删除资源 |

## 16. 风险与开放项

| 风险/开放项 | 说明 | 处理 |
|---|---|---|
| **云端是否限制不可识别的加密大文件** | 全案前提是"云端扫不出内容→不限制"。 | **M0 必测**。 |
| 忘记主密码 = 锁死 | 无主密码不可解。 | 恢复密钥兜底（§7）；引导离线保管。 |
| 百度应用凭证获取 | 用户需自备开放平台应用凭证；个人应用创建可能受限。 | 文档指引；作为已知外部依赖记录。 |
| QPS / 配额未知 | 官方未公开。 | M0 实测，据此设并发/退避。 |
| 百度接口/政策变动 | API/政策可能调整。 | 核心库隔离对接层，便于适配。 |

## 17. 附：数据流

```
上传：原文件 →(可选压缩)→ AES-256-GCM 加密(DEK) →切 100MB 分片→ 生成预览包
      → 写 manifest(wrappedKey=KEK(主密码)(DEK)+encMeta) → precreate/superfile2/create 上传到 /apps/bizhou/<id>.bz/
下载：列 bundle → 读 manifest → 主密码解 KEK → 解 DEK → 下载分片 → 解密 → 合并 → 还原
分享：生成分享码(导出 DEK)；或 `bz share --7z` 导出 7z-AES 单包
```

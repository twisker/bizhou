# 敝帚 发布准备指南（npm + Homebrew tap + Scoop bucket）

面向人工执行。目标：让用户能通过三种方式安装 `bz`：

- `npm i -g @<scope>/cli`（跨平台，需 Node）
- macOS/Linux：`brew tap <你>/bizhou && brew install bizhou`
- Windows：`scoop bucket add bizhou <url> && scoop install bizhou`

本仓库已备好发版脚本 `scripts/gen-packaging.sh`：构建 → 打确定性 tarball → 算 sha256 → 生成 Homebrew formula + Scoop manifest。你只需按下文准备好账号/仓库，再把产物发上去。

> 约定：下文 `<GH_USER>` = 你的 GitHub 用户名（本仓库默认 slug 为 `xkool/bizhou`，可用 `BIZHOU_REPO_SLUG` 覆盖）。命令里凡 `<...>` 都请替换成你的实际值。

---

## 0. 决策：npm 包 scope（你已有组织 `twisker`）

当前包名是 `@bizhou/core` 与 `@bizhou/cli`。`@bizhou` 这个 scope 需要你在 npm 上**拥有名为 `bizhou` 的组织或用户名**。你现在有的是 `twisker`，所以二选一：

| 方案 | 做法 | 优缺点 |
|---|---|---|
| **A. 新建 npm 组织 `bizhou`（推荐）** | 在 https://www.npmjs.com/org/create 免费建 public 组织 `bizhou`，保持 `@bizhou/core`/`@bizhou/cli` 不变 | 品牌统一、包名短；多一个组织要管 |
| **B. 用现有 `twisker` scope** | 把包重命名为 `@twisker/bizhou-core`、`@twisker/bizhou-cli` | 复用已有组织；包名略长；**需改代码**（package.json 的 name 与 workspace 依赖引用），改完我来做 |

- public scoped 包发布免费；发布时必须带 `--access public`。
- **选定后告诉我**：选 B 的话我改 `packages/*/package.json` 的 `name` 与 CLI 对 core 的依赖引用，并同步 README/文档里的包名。
- 下文 npm 步骤以 `<scope>` 表示（`bizhou` 或 `twisker`）。

## 1. npm 发布

### 1.1 一次性准备
```bash
npm login                      # 登录你的 npm 账号（能操作 <scope> 组织）
# 方案 A 若尚未建组织：浏览器打开 https://www.npmjs.com/org/create 建 public 组织 bizhou
```

### 1.2 发布前的一个代码微调（CLI 依赖）
CLI 产物已把 `@bizhou/core` **打包进自身**（`noExternal`），所以发布的 CLI 运行时**不需要**再依赖 core。发布前把 CLI 的 core 依赖从 `dependencies` 移到 `devDependencies`，避免用户 `npm i -g` 时被迫再装一份 core：

> 这步我可以帮你改（`packages/cli/package.json`）。若你先发 `@<scope>/core` 再发 CLI，也可不改——但推荐移到 devDependencies 更干净。

### 1.3 发布（用 pnpm，自动把 workspace:* 换成真实版本，并套用 publishConfig 指向 dist）
```bash
pnpm run build                                   # 生成两包 dist
pnpm --filter @<scope>/core  publish --access public --no-git-checks
pnpm --filter @<scope>/cli   publish --access public --no-git-checks
```
验证：
```bash
npm view @<scope>/cli version
npm i -g @<scope>/cli && bz --version
```

## 2. GitHub 主仓库 + Release（Homebrew/Scoop 从这里下载 tarball）

### 2.1 建主仓库并推送
```bash
gh repo create <GH_USER>/bizhou --public --source=. --remote=origin --push
# 或手动：git remote add origin git@github.com:<GH_USER>/bizhou.git && git push -u origin <当前分支>
```
> `git push` 一直由你手动执行（H-07）。当前开发分支是 `feature/init_proj`；正式发布前建议合并到 `main`。

### 2.2 打里程碑版本（M0+M1 完成，建议升 minor 或直接 1.0.0）
```bash
scripts/bump-minor.sh          # 0.1.x → 0.2.0（会自动 commit）
# 或首个正式版： 手动把 VERSION 改成 1.0.0 再 git commit
```

### 2.3 生成产物并建 Release
```bash
export BIZHOU_REPO_SLUG=<GH_USER>/bizhou
bash scripts/gen-packaging.sh          # 产出 packaging/generated/{bizhou-cli-<v>.tgz, bizhou.rb, bizhou.json}
V=$(cat VERSION)
gh release create "v$V" "packaging/generated/bizhou-cli-$V.tgz" \
  --title "v$V" --notes "敝帚 v$V：客户端加密引擎 + CLI"
```
> `gen-packaging.sh` 生成的 `bizhou.rb` / `bizhou.json` 里的 `url` 与 `sha256` 已对应这个 Release 的 tarball，直接用于下面两步。

## 3. Homebrew tap 仓库

Homebrew「tap」= 一个名为 **`homebrew-<tap名>`** 的 GitHub 仓库，里面放 `Formula/*.rb`。用户 `brew tap <GH_USER>/<tap名>` 后即可 `brew install`。

### 3.1 建 tap 仓库（tap 名用 `bizhou`）
```bash
gh repo create <GH_USER>/homebrew-bizhou --public --clone
cd homebrew-bizhou
mkdir -p Formula
cp ../bizhou/packaging/generated/bizhou.rb Formula/bizhou.rb
git add Formula/bizhou.rb
git commit -m "bizhou <版本>"
git push
cd ..
```

### 3.2 用户安装
```bash
brew tap <GH_USER>/bizhou
brew install bizhou
bz --version
```

### 3.3 每次发新版
重新跑 `gen-packaging.sh`（新版本号+新 sha256）→ 覆盖 `homebrew-bizhou/Formula/bizhou.rb` → commit + push。用户 `brew update && brew upgrade bizhou`。

---

## 4. Scoop bucket 仓库（Windows）

Scoop「bucket」= 一个 GitHub 仓库（惯例名 **`scoop-<name>`**），放 manifest json。

### 4.1 建 bucket 仓库
```bash
gh repo create <GH_USER>/scoop-bizhou --public --clone
cd scoop-bizhou
mkdir -p bucket
cp ../bizhou/packaging/generated/bizhou.json bucket/bizhou.json
git add bucket/bizhou.json
git commit -m "bizhou <版本>"
git push
cd ..
```

### 4.2 用户安装（Windows PowerShell）
```powershell
scoop bucket add bizhou https://github.com/<GH_USER>/scoop-bizhou
scoop install bizhou
bz --version
```
> Scoop manifest 里 `"depends": "nodejs"`，用户需先 `scoop install nodejs`（或已装 Node）。

### 4.3 每次发新版
重跑 `gen-packaging.sh` → 覆盖 `scoop-bizhou/bucket/bizhou.json` → commit + push。用户 `scoop update bizhou`。

---

## 5. 发版清单（每次发布照做）

1. `scripts/bump-minor.sh`（或改 VERSION）→ commit。
2. `export BIZHOU_REPO_SLUG=<GH_USER>/bizhou && bash scripts/gen-packaging.sh`。
3. `git push`（人工）+ `gh release create "v$(cat VERSION)" packaging/generated/bizhou-cli-*.tgz`。
4. `pnpm --filter @<scope>/core publish --access public` + `... cli ...`。
5. 覆盖并推送 `homebrew-bizhou/Formula/bizhou.rb`、`scoop-bizhou/bucket/bizhou.json`。
6. 冒烟：`brew upgrade bizhou`、`scoop update bizhou`、`npm i -g @<scope>/cli` 各验一次 `bz --version`。

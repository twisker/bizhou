# 敝帚 v1.1.0 实现计划 —— 云端保险库与配套能力

> **For agentic workers:** 用 superpowers:subagent-driven-development 逐任务执行。步骤用 `- [ ]` 勾选。

**Goal:** 让保险库可加密上云，从而"换机只需重输主密码"这句话第一次真正成立；同时补齐回收站、配额查询、恢复密钥重导出。

**Architecture:** 先给 `Backend` 加一组通用 blob 原语（当前只有 bundle 专用读写），云端保险库建在其上；CLI 负责交互与升级提示，核心库保持无交互。

**Tech Stack:** TypeScript · Bun test（现有 221 用例必须全绿）· 零新增运行时依赖

---

## Global Constraints

- **核心库只发进度事件、绝不 print**；所有交互（口令、确认、提示）留在 CLI 层
- **核心库不得使用 Bun 专有 API**，须在 Node LTS 下等价运行
- **密钥/凭证绝不入库、绝不进日志**
- 解密失败必须报错，**绝不静默返回损坏数据**
- 现有 **221 个测试全绿**是每个任务的完成前提
- `kdf` 参数存在每个 vault 文件内 → **参数变更必须向前兼容**，老 vault 用老参数照常解锁
- 版本：本批完成后 `VERSION` 与两个 package.json 升至 **1.1.0**（人工触发 `scripts/bump-minor.sh`）

### 三条本批特有的定性（写进代码注释，防后人误解）

1. **云端文件名不是安全边界。** 引擎开源，命名规则对手可读。"不透明"只降低朴素模式匹配的命中率，**不提供保密性**。保密性来自 scrypt 参数 + 用户主密码强度。
2. **vault 上云改变威胁模型。** 上云前攻击者需先拿到设备；上云后云服务商直接持有密文，可离线无限次爆破。这是用主密码强度换换机可恢复性的**自觉交易**，必须让用户知情。
3. **对存量弱密码用户这是安全降级。** 因此升级路径必须：强提示 + 强度检查 + 不够强先改密码（人工裁定 2026-07-25：默认上云，升级时强提示）。

# 常见问题 FAQ

### 忘了主密码怎么办？
用 `bz recover` + 初始化时生成的**恢复密钥**重设主密码。**两者都丢** = 数据无法解密（端到端加密的必然）。请务必离线保存恢复密钥。

恢复密钥解的是**保险库**里那份密文。v1.1.0 起保险库默认有一份加密副本存在云端，因此换机时只要能登录网盘就能取回；若你当初用 `bz init --no-cloud-vault` 选择了只留本地，那就必须保证本机 `vault.json`（默认在 `~/.bizhou`）还在。

忘了自己有没有恢复密钥？`bz vault recovery-key` 可以重新导出**同一串**（需重输主密码）；v1.1.0 之前建的保险库用 `bz vault recovery-key --rotate` 换一串新的。

### 换了电脑 / 重装系统，数据还在吗？

**在。** v1.1.0 起 `bz init` 会把**保险库的加密副本**放到你自己的网盘里，因此换机只需两步：

```bash
bz login      # 登录同一个百度账号
bz unlock     # 输入主密码 —— 保险库自动从云端取回
```

之后 `bz ls` / `bz pull` 一切照旧。

**这背后的取舍，你有权知道：** 保险库上云意味着百度手里有了这份密文，可以**离线、不限次数**地尝试猜你的主密码（在此之前，攻击者得先拿到你的设备）。换来的是"设备没了数据还在"。所以：

- `bz init` 会**拦下**强度不足的主密码，不达标就不许上云——这不是唠叨，是这笔交易能否成立的前提。
- 推荐用四五个不相干的词组成的长短语（既更强也更好记），而不是塞满符号的短密码。
- 想彻底不上云：`bz init --no-cloud-vault`。代价是换机、重装、硬盘损坏都会让云端数据**永久锁死**，此时必须自己备份密钥根：

  ```bash
  cp -a ~/.bizhou ~/bizhou-密钥根备份     # 与恢复密钥分开存放
  ```

**v1.0.x 的老用户**：你的保险库还只在本机。跑一次 `bz vault sync`（或直接 `bz unlock`，会顺带补传）即可补上；主密码不够强时会被拦下并提示先 `bz passwd`。用 `bz vault status` 随时查看本机与云端的状态。

### 别人在百度网盘里能看到什么？
一堆随机名的 `.bz` 文件夹（你建的目录结构可见），里面是密文分片。看不到原文件名、内容、大小。见 [安全模型](./security.html)。

### 重复上传同一个文件会怎样？
自动去重跳过——push 前算内容指纹，目标目录已有相同内容就不再传。用 `--force` 可强制。

### 上传/下载传到一半断了？
直接**重跑同一条命令**续传（复用同一密钥与已完成分片）。下载写临时文件、完成才原子落地并做端到端校验，绝不交付半份文件。

### 单文件有大小上限吗？
按 100MB 逻辑分片规避百度单文件上限（`--chunk` 可调）。已实测 >4GB 大文件往返字节一致。

### 一定要装 ffmpeg / pdftoppm 吗？
不。它们只用于**预览生成**且可选——缺失时对应预览优雅跳过，**不影响加密上传/下载**。文本/压缩包列表预览零外部依赖。

### daemon 会占用/删除我的云端文件吗？
**永不删云**。daemon 只增/更新（备份语义）；本地删文件不会镜像删除云端备份。清云端请用 `bz rm` / `bz trash`。

### 支持哪些 shell 补全？
bash / zsh / PowerShell（`bz completion <shell>`）。见 [分享与 shell 补全](./guide-share-completion.html)。云端 bundle id / 路径的动态补全本轮未做。

### 这工具会不会偷偷内嵌百度凭证？
不会。凭证**用户自备**（`.env` 里的 AppKey/SecretKey），代码中无任何硬编码秘密。

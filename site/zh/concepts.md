# 核心概念

## 端到端加密（密钥不出端）

- 文件内容用 **AES-256-GCM** 加密（AEAD：既保密又防篡改；任何篡改或错误口令都会校验失败而**报错**，绝不返回损坏数据）。
- **信封 + 主密钥 MK 间接**：
  - 每个资源随机生成一把 **DEK** 加密其内容；
  - 一把随机 **主密钥 MK** 用来包裹（加密）各资源的 DEK；
  - MK 本身被两条路径各包裹一份：**主密码派生的 KEK**、**恢复密钥**。
- 好处：**改主密码**只需重新包裹 MK，不动任何资源；**忘主密码**用初始化时生成的**恢复密钥**解出 MK。没有主密码或恢复密钥，任何人都解不开 MK → 解不开任何 DEK → 读不到内容。

## Bundle（资源的物理形态）

每个「资源」是一个带 `.bz` 后缀的**文件夹**（在别的网盘客户端里就是个普通文件夹）：

```
<opaque-id>.bz/
  ├── manifest.json   # 分片信息 + wrappedKey(MK 包裹的 DEK) + encMeta(加密元数据) + 预览指向
  ├── 000.part        # 加密分片（默认每片 ≤100MB）
  ├── 001.part
  └── preview.part    # 加密预览包（可选）
```

- **文件夹名不透明、不含原文件名**；原文件名、大小、内容指纹都只存在**加密的** `encMeta` 里。
- 大文件按 **100MB 逻辑分片**（可 `--chunk` 调），规避单文件上限；内存占用与文件大小解耦（任一时刻只有一片驻留内存）。

## 云端随机名 + 本地真名

- **云端**保留**随机 bundle 名**（隐私：别人看你的网盘只见一堆无意义文件夹）。
- **本地 / `bz ls`** 显示**真名**——从解密的 `encMeta` 读出。
- **真实目录树**：云端与本地都是真实目录，可 `mkdir` / `ls -r` / `mv` / `cp` / `rename`。

## 双本地根

| 根 | 存什么 | 默认 | 环境变量 |
|---|---|---|---|
| **密钥根** | 密钥、账号、配置、备份任务、上传/下载日志、缓存 | `~/.bizhou` | `BIZHOU_HOME` |
| **文件根** | 下载还原后的文件 | 系统「下载」目录 | `BIZHOU_FILE_ROOT` |

- **上传映射**：`push` 缺省把源文件按相对文件根的位置镜像到云端；`--to` 显式指定云端目录。源文件**不必**在文件根之下。
- **下载映射**：`pull` 把云端目录结构带入文件根之下作为子目录还原。

## 内容指纹（去重的基础，且不泄露）

- 去重靠**内容指纹** `contentId = HMAC(派生自 MK 的密钥, 明文)`。
- 它只存进**加密的** `encMeta`，云端零可见；带密钥 → 不是裸哈希、不同账号无法互相关联。
- 同明文 → 同 contentId（同一 vault 内稳定），于是能识别「这文件已经传过了」。

## 幂等 · 续传 · 在飞锁

- **幂等去重**：push 前先算 contentId，若目标目录已有相同内容的完成 bundle → 跳过。
- **续传**：中断后重跑，复用同一 bundleId + 同一 DEK + 已完成分片；下载写临时文件、完成才**原子改名**落地，并做**端到端 contentId 校验**。
- **在飞锁**：同内容正在传到同目的地 → 提醒并结束，防并发重复。
- 这些都由本地「日志」文件承载（密钥根下），既是锁也是续传状态，绝不含任何密钥。

## 分片器与并发

- 上传：可选压缩 → AES-GCM 加密 → 逐 100MB 逻辑分片 → 每片再切 4MB 传输分片上传。
- **并发**在片内 4MB 层（限流池，`--concurrency` 默认 4）——因为瓶颈在网络 I/O 而非 CPU 加密。

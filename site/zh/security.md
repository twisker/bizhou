# 安全模型

## 算法与参数

| 用途 | 方案 |
|---|---|
| 内容加密 | **AES-256-GCM**（AEAD：机密性 + 完整性/防篡改） |
| 口令派生 KEK | **scrypt**（口令先 NFKC 归一化，加盐、参数化，写入 vault 可审计） |
| 密钥包裹 | AES-256-GCM 信封（KEK 包裹 MK；MK 包裹各资源 DEK） |
| 内容指纹 | **HMAC-SHA256**（密钥由 MK 经 HKDF 派生） |
| 分片 IV | 确定性派生 `HMAC-SHA256(DEK, "<bundleId>:<seq>")[:12]`，续传时固定 chunkSize/compression 保证唯一（详见 tech-spec §5.1.1） |

零外部加密依赖：AES-GCM 与 KDF 全用运行时**内置 `crypto`**，跨平台一致、可审计。

## 密钥体系（信封 + MK 间接）

```
主密码 ──scrypt──▶ KEK_pw ─┐
                            ├─包裹─▶  MK（随机主密钥）──包裹─▶ 各资源 DEK ──▶ 加密内容
恢复密钥 ───────▶ KEK_rk ─┘
```

- **MK** 只生成一次；每个资源的 DEK 由 MK 包裹后存进该资源 `manifest.wrappedKey`。
- **改主密码**：只重新包裹 MK（换 KEK_pw），不动任何资源。
- **忘主密码**：用初始化时给的**恢复密钥**解出 MK。
- 没有主密码或恢复密钥 → 解不开 MK → 解不开任何 DEK → **读不到任何内容**。真端到端。

## 云端看得到什么 / 看不到什么

| 云端可见 | 云端不可见 |
|---|---|
| 随机 bundle 文件夹名（无原文件名） | 文件内容（只有密文） |
| 分片数量与各分片**密文**大小 | 原文件名、大小、mtime（在加密 encMeta 里） |
| manifest 中的 iv/tag/密文 sha256 | 内容指纹（HMAC，在加密 encMeta 里，且带密钥） |
| 目录树结构（你建的真实目录） | 主密码、恢复密钥、DEK、MK（全程不出端） |

> 若你介意暴露**目录结构本身**，可把所有 bundle 放同一层、用 `--to` 归拢。

## 威胁模型（防什么 / 不防什么）

**能防：**
- 云端 / 网络中间人**读取内容**：只见密文，GCM 保证机密。
- 云端**篡改内容**：GCM tag 校验失败即报错，绝不返回损坏数据；分片 AAD 绑定 `(bundleId, seq)`，防止调换/移花接木；下载还做端到端 contentId 校验。
- **确认攻击**：内容指纹是带密钥 HMAC 且只存加密 encMeta，攻击者即使握有候选明文也无法确认你存了它。
- **换机/丢机**：密钥不在云端；新机重输主密码即可。

**不防（超出范围）：**
- **你的设备被攻破**：主密码/主密钥在本机内存与钥匙串中；本机失守则失守。
- **弱主密码被暴力破解**：请用强主密码（scrypt 增加成本，但不能救太弱的口令）。
- **元数据推断**：分片数量/大小、目录结构等旁路可被观察（见上表）。
- **可用性**：备份不删云是防误删，但不替代多副本容灾。

## 隐私红线（工程约束）

- 密钥/凭证**绝不入库、绝不写明文日志**；`.env`、vault、device.key、token 一律不提交、不 print、不进测试快照。
- 核心库**只发进度事件、绝不 print**；所有口令输入/确认留在 CLI 层。
- 上传日志 / 备份配置 / manifest 缓存**均无密钥**（只存 id/seq/时间/pid/MK 包裹的 wrappedKey/加密态 manifest）。
- 任何解密路径遇 GCM 校验失败/错误主密码，必须**报错**，绝不静默返回损坏数据。

## 备份你的恢复密钥

`bz init` 生成的**恢复密钥是唯一的忘密码兜底**。请离线抄下、妥善保存（密码管理器 / 纸质保险箱）。丢了主密码又丢了恢复密钥 = 数据永久无法解密（这正是端到端加密的代价与保证）。
